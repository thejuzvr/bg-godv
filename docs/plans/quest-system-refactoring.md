# Рефакторинг системы заданий (Quest System Refactoring)

## Текущая ситуация

### Проблемы:

1. **Дублирование систем заданий:**
   - Старая система: `activeSovngardeQuest`, `activeCryptQuest` (JSONB поля в таблице `characters`)
   - Новая система: таблицы `quests` и `quest_tasks`
   - Два разных подхода работают параллельно, создавая путаницу

2. **Ограничение на количество активных заданий:**
   - Сейчас в `questService.ts` (строка 88-91) есть проверка: один персонаж = одно активное задание
   - Это искусственное ограничение мешает развитию gameplay

3. **Нет универсальной панели прогресса:**
   - `QuestProgressPanel` работает только с новой системой (quest_tasks)
   - Старые квесты (Sovngarde, Crypt) не отображаются в прогрессе
   - Нет единого интерфейса для отображения любого типа задания

4. **Нет приоритизации заданий:**
   - AI не знает, какое задание важнее
   - Нет системы "текущее задание" vs "фоновые задания"
   - Hero может браться за новые задания, игнорируя взятые

## Архитектура решения

### 1. Унификация типов заданий

Все задания должны использовать таблицы `quests` и `quest_tasks`. Два типа:

#### Тип А: Однозадачные (Simple Quest)
- Одно задание без подзадач
- progress: 0-100 (общий прогресс)
- Примеры: "убить бандита", "принести предмет"

#### Тип Б: Многозадачные (Multi-step Quest)
- Задание с подзадачами (quest_tasks)
- progress рассчитывается автоматически на основе выполненных подзадач
- Примеры: "Квест Совнгарда" (поговорить с NPC -> дойти до локации -> сразиться -> вернуться)

### 2. Схема базы данных (текущая - уже хорошая!)

```sql
-- quests (уже есть)
id, character_id, template_id, title, description, location, type, status, rewards, progress, metadata, expires_at

-- quest_tasks (уже есть)
id, quest_id, idx, title, type, status, progress, data
```

**Важно:** Для однозадачных квестов просто не создаём записи в `quest_tasks`.

### 3. Новые поля для приоритизации

Добавить в таблицу `quests`:
- `priority` (integer, default 50) - приоритет задания (0-100, где 100 = высший приоритет)
- `is_active` (boolean, default false) - текущее активное задание
- `can_auto_complete` (boolean, default true) - может ли AI автоматически выполнять это задание

### 4. Логика приоритизации

```typescript
// Правила приоритизации:
// 1. Только одно задание может быть is_active = true одновременно
// 2. AI фокусируется на is_active задании
// 3. Можно иметь множество заданий со status = 'in-progress', но не is_active
// 4. При выборе следующего действия AI проверяет:
//    - Есть ли is_active задание? -> Работать над ним
//    - Нет is_active? -> Выбрать задание с наивысшим priority и сделать его is_active
// 5. Игрок может вручную установить is_active через "божественное вмешательство"
```

   - Открыть журнал заданий

   - is_active = false, status = 'completed'
   - AI автоматически выбирает следующий квест по priority

## Детали реализации Progress Bar

### Расчёт прогресса для multi-step квестов

```typescript
function calculateQuestProgress(quest: QuestDB, tasks: QuestTaskDB[]): number {
  if (tasks.length === 0) {
    // Однозадачный квест - используем quest.progress
    return quest.progress;
  }
  
  // Многозадачный квест - считаем на основе подзадач
  const totalTasks = tasks.length;
  const completedTasks = tasks.filter(t => t.status === 'completed').length;
  const inProgressTasks = tasks.filter(t => t.status === 'in-progress');
  
  // Базовый прогресс: выполненные подзадачи
  let progress = (completedTasks / totalTasks) * 100;
  
  // Добавляем частичный прогресс для подзадач in-progress
  inProgressTasks.forEach(task => {
    progress += (task.progress / 100) * (1 / totalTasks) * 100;
  });
  
  return Math.min(100, Math.floor(progress));
}
```

### Пример расчёта:

Квест с 4 подзадачами:
- ✅ Задача 1: completed (100%)
- ✅ Задача 2: completed (100%)
- ⚙️ Задача 3: in-progress (50%)
- ⏳ Задача 4: pending (0%)

Расчёт:
- Выполнено: 2/4 = 50%
- В процессе: 50% * (1/4) = 12.5%
- Итого: 50% + 12.5% = 62.5% ≈ 62%
